코딩 방식 결정
귀납적(오픈) vs 연역적(사전 코드 있음). 없으면 귀납으로 시작.

단계별 실습

1
전사본 정제 (구어체 → 가독성 개선)Claude

녹음을 직접 전사하면 '어', '음', 말 더듬기, 비완성 문장이 많습니다. 연구 분석에 앞서 가독성을 높이는 정제 작업을 먼저 합니다.

프롬프트

아래는 인터뷰 녹취 전사본입니다. 다음 기준으로 정제해 주세요:

1. '어', '음', '그러니까', '뭐랄까' 등 말 더듬 표현 제거
2. 비완성 문장은 의미를 유지하며 완성형으로 정리
3. 의미가 같은 반복 표현은 한 번만 남기기
4. 원래 표현의 뜻을 바꾸지 말 것 (내용 수정 금지)
5. 화자 구분은 [연구자] / [참여자]로 표시

[전사본 텍스트 붙여넣기]

2
연구 맥락 설명 + 오픈코딩 요청Claude

오픈코딩 전에 연구 질문과 분석 목적을 Claude에 설명합니다. 이 맥락이 없으면 코드가 피상적으로 나올 수 있습니다.

프롬프트

이 인터뷰의 연구 질문은 "[예: 초등교사가 AI 도구를 수업에 통합할 때 경험하는 어려움은 무엇인가?]"입니다.

위 정제된 전사본을 귀납적 오픈코딩(open coding)으로 분석해 주세요:

- 각 의미 단위(문장 또는 단락)에 코드명을 부여
- 코드명은 참여자의 언어를 최대한 반영한 In vivo code 우선
- 형식: [인용문] → 코드명
- 같은 내용이 반복되면 같은 코드명 재사용
- 중립적 언어 사용, 해석 최소화

Claude — 오픈코딩 결과 예시
Claude

[오픈코딩 결과] "AI가 뭘 할 수 있는지 잘 모르겠어요, 그냥 챗봇이랑 다른 거 아닌가요?" → AI 기능에 대한 불명확한 인식 "써보고 싶긴 한데 뭘 어떻게 써야 할지..." → 활용 방법 모름 / 시작의 어려움 "학교에서 공식 허용이 된 건지 안 된 건지..." → 기관 차원의 허용 기준 불명확 "수업 준비 시간이 오히려 더 걸리는 것 같아서요" → 효율성에 대한 의구심

3
코드 목록 확인 및 정리연구자

코딩 후 중복되거나 너무 세분화된 코드를 연구자가 직접 정리합니다. 이 단계는 Claude가 보조하되, 최종 결정은 연구자가 합니다.

프롬프트

위에서 도출된 코드 목록 전체를 정리해서 보여주세요. 그리고 의미가 유사하거나 통합할 수 있는 코드를 추천해 주세요. (최종 결정은 제가 하겠습니다)

💡 팁

코드가 30개 이상 나오면 너무 세분화된 것입니다. 주제별로 묶어 10~20개로 줄이는 것을 목표로 하세요.

4
범주화(축 코딩) 및 주제 도출Claude

정리된 코드를 상위 범주로 묶고, 범주 간의 관계를 파악하여 연구 주제를 도출합니다.

프롬프트

정리된 코드들을 2~4개의 상위 주제(theme)로 범주화해 주세요.

형식:
- 주제명 (핵심 개념을 담은 명사구)
- 해당 주제를 구성하는 하위 범주
- 하위 범주에 속하는 코드들
- 주제를 뒷받침하는 대표 인용문 1~2개

코딩 트리 예시 (초등교사 AI 도구 통합 어려움)
주제 1: AI에 대한 불명확한 인식과 기대
범주: AI 기능 이해 부족 범주: 효용성 불확실
AI 기능 불명확한 인식 챗봇과의 혼동 효율성 의구심 학습 시간 부담
주제 2: 제도적·환경적 지원 부재
범주: 기관 허용 기준 모호 범주: 연수·지원 부족
허용 여부 불명확 공식 가이드라인 부재 동료 지원 없음
5
분석 결과 서술문 초안 작성Claude

주제가 확정되면 결과 섹션에 쓸 서술문 초안을 요청할 수 있습니다.

프롬프트

위에서 도출된 주제를 바탕으로 질적 연구 결과 섹션의 서술문 초안을 작성해 주세요.

조건:
- 각 주제당 2~3개 단락
- 참여자 인용문을 직접 인용으로 포함 (따옴표 처리)
- 인용 후 연구자의 해석 문장 추가
- 분석적이되 평가적이지 않은 중립적 문체
- 참여자 표기: 참여자1, 참여자2 형식

완료 체크리스트

  • 전사본의 구어체가 정제되어 가독성이 높아짐
  • 오픈코딩이 완료되고 코드 목록이 정리됨
  • 중복·유사 코드가 통합되어 10~20개 이내로 압축됨
  • 2~4개의 상위 주제로 범주화됨
  • 각 주제에 대표 인용문이 1개 이상 확보됨
  • 결과 서술문 초안이 작성됨
⚠️ 중요

Claude는 코딩 작업의 보조 도구입니다. 귀납적 질적 연구에서 코드의 최종 결정과 해석의 책임은 연구자에게 있습니다. 연구자가 각 인용문을 직접 읽고 코드의 적절성을 확인하는 과정을 반드시 거쳐야 합니다.
