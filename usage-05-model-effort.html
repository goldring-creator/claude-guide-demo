모델 선택과 사고 깊이 설정

Claude Code에서 /model과 /effort를 조절하는 방법 — 연구 작업의 복잡도에 맞게 품질과 비용을 최적화합니다.

이 페이지에서 배우는 것

단축키와 명령어 전반은 활용 02 — 단축키와 슬래시 명령어를 참고하세요. 이 페이지는 /model과 /effort 두 명령어를 깊이 있게 다룹니다.

1. 왜 모델과 사고 깊이를 조절해야 하는가

Claude Code는 기본 설정만으로도 대부분의 작업을 잘 처리합니다. 하지만 연구자로서 두 가지 상황을 자주 마주칩니다.

  • 정밀도가 필요한 작업 — 통계 분석 설계, 복잡한 논문 구조 기획, HLM 모형 선택처럼 깊은 추론이 요구되는 경우
  • 반복적인 단순 작업 — 영문 초록 번역, 참고문헌 형식 통일, 간단한 요약처럼 빠른 처리가 더 중요한 경우

모델과 사고 깊이를 상황에 맞게 조절하면 중요한 작업의 품질을 높이면서 전체 비용을 줄일 수 있습니다.

2. 모델 선택 — /model

인수 없이 /model을 입력하면 피커가 열립니다. 피커에서 좌우 방향키로 effort 슬라이더도 함께 조정할 수 있습니다.

모델 별칭(Alias) 완전 가이드

별칭실제 모델특징추천 연구 작업
sonnet 최신 Sonnet 속도·품질 균형, 대부분 작업에 충분 문헌 정리, 초록 교정, 코드 실행
opus 최신 Opus 가장 강력한 추론, 복잡한 설계에 적합 연구 설계, 방법론 검토, 통계 전략
haiku 최신 Haiku 매우 빠르고 저렴, 간단한 작업용 단순 번역, 형식 변환, 빠른 요약
opusplan 계획=Opus
실행=Sonnet		 계획 단계에만 Opus를 사용하고 실행은 Sonnet으로 자동 전환 복잡한 다단계 작업, 논문 분석, HLM 설계
opus[1m] Opus + 1M 컨텍스트 100만 토큰 컨텍스트 창, 매우 긴 세션 가능 대용량 문서 분석, 긴 세션 연구
sonnet[1m] Sonnet + 1M 컨텍스트 Sonnet 속도에 긴 컨텍스트 추가 대용량 코드베이스, 긴 연구 데이터 
/model opusplan    # 계획=Opus, 실행=Sonnet
/model sonnet      # 일반 작업으로 돌아오기
/model             # 피커 열기 (방향키로 effort 동시 조정)

opusplan — 가장 실용적인 전략

opusplan은 Claude Code에서 제공하는 하이브리드 모드입니다. Shift+Tab으로 plan mode on을 활성화하면 Opus가 계획을 세우고, 실행 단계로 전환되면 자동으로 Sonnet이 이어받습니다.

계획이 정밀하면 실행은 기계적입니다 — 고비용 Opus를 핵심 단계에만 집중 투입합니다.
💡 건축가와 시공팀 비유

Opus는 설계도를 그리는 건축가입니다. Sonnet은 그 설계도를 따라 짓는 시공팀입니다. 설계가 정밀할수록 시공팀은 실수 없이 빠르게 완성합니다. 비용이 높은 건축가를 설계에만 쓰는 게 합리적입니다.

3. 사고 깊이 — /effort

모델이 무엇을 할지를 정한다면, effort는 얼마나 깊이 생각할지를 정합니다. 높은 effort는 토큰(비용)을 더 소모하지만 복잡한 작업에서 품질 차이가 납니다.

low

high

비용 절감

복잡한 분석
최고 난이도
레벨기본값 여부세션 간 유지추천 연구 상황
low — ✅ 유지 영문 초록 번역, 참고문헌 형식 통일, 단순 요약
medium Pro·Max 플랜 기본 ✅ 유지 비용이 중요한 작업, 문헌 목록 정리
high Opus 4.6·Sonnet 기본 ✅ 유지 일반 논문 작성, 데이터 분석 코드 작성
xhigh Opus 4.7 기본 ✅ 유지 복잡한 통계 설계, HLM·SEM 방법론, 논문 심사 대응
max — ❌ 세션한정 가장 까다로운 일회성 작업 (과도한 사용은 역효과 가능) 
/effort xhigh    # 직접 설정
/effort          # 인터랙티브 슬라이더
/effort auto     # 모델 기본값으로 리셋
💡 ultrathink — 일회성 최대 추론

effort 설정을 바꾸지 않고 특정 답변에서만 최대로 깊이 생각하게 하려면 프롬프트에 ultrathink를 포함하세요.

예: "이 연구 방법론의 한계를 ultrathink로 검토해줘"
"패널데이터 분석 전략을 ultrathink로 설계해줘"

4. 세 가지의 연계 — Shift+Tab · /model · /effort

세 설정을 조합하면 각 연구 상황에 최적화된 환경을 만들 수 있습니다.

최강 조합 — 복잡한 연구 설계

1. /model opusplan → 계획은 Opus, 실행은 Sonnet
2. /effort xhigh → 깊은 추론 활성화
3. Shift+Tab → plan mode on 전환 후 설계 요청
4. 계획 확인 후 다시 Shift+Tab → 일반 모드로 실행

연구 시나리오별 추천 설정

시나리오 01
논문 분석 설계 · HLM · SEM
/model opusplan /effort xhigh Shift+Tab → plan mode on
복잡한 설계 오류는 이후 전체에 영향. 계획 단계에 Opus·xhigh 집중 투입.
시나리오 02
일반 R 코드 작성 · 데이터 정리
/model sonnet /effort high
Sonnet·high 조합으로 충분한 품질을 빠르게. 기본 설정과 같아 별도 변경 불필요.
시나리오 03
영문 초록 번역 · 형식 정리
/model sonnet /effort low
반복적 단순 작업. low effort로 속도와 비용 모두 절감.
시나리오 04
심사 의견 반박문 작성
/model opus /effort xhigh
심사위원 관점의 정밀한 논리 구성이 필요. Opus·xhigh로 논증 품질 최대화.
시나리오 05
긴 세션 — 대용량 문헌 분석
/model sonnet[1m] /effort high
컨텍스트가 많이 필요한 경우 1M 윈도우를 활용. Opus[1m]은 더 강력하지만 추가 비용 확인.
시나리오 06
일회성 초고난도 작업
/model opus /effort max ← 세션 한정
max는 세션 종료 후 자동 해제. 과도한 사용은 오히려 overthinking 위험. 꼭 필요할 때만.

5. CLAUDE.md에 영구 설정하는 방법

매 세션마다 명령어를 입력하기 번거롭다면 CLAUDE.md나 Claude Code 설정 파일에 기본값을 지정할 수 있습니다.

방법 1 — CLAUDE.md에 지시 추가

프로젝트의 CLAUDE.md에 아래처럼 기본 설정을 명시하면 Claude가 매 세션 시작 시 읽습니다.

# 기본 설정
- 복잡한 분석 작업에는 /model opusplan과 /effort xhigh를 사용한다.
- 단순 번역·형식 작업에는 /effort low를 사용한다.
- 새 세션 시작 시 현재 작업 성격에 맞는 모델과 effort를 자동으로 제안한다.

방법 2 — 환경 변수로 고정

프로젝트의 .env 파일에 추가하면 항상 적용됩니다.

# .env
ANTHROPIC_MODEL=opusplan
CLAUDE_CODE_EFFORT_LEVEL=xhigh
주의 — max는 환경 변수로 고정 가능하지만 신중하게

CLAUDE_CODE_EFFORT_LEVEL=max로 설정하면 모든 작업에 최대 추론이 적용됩니다. 단순 작업에서도 높은 토큰을 소모하므로 일반적으로 권장하지 않습니다. xhigh가 대부분 상황에서 최적입니다.

✅ 이 장을 마쳤다면

/model opusplan으로 계획과 실행 모델을 분리하는 전략을 이해했고, /effort로 사고 깊이를 작업에 맞게 조절할 수 있습니다. Shift+Tab으로 plan mode를 활성화하고 opusplan과 함께 쓰는 조합이 핵심입니다. 단순 번역에는 sonnet + low, 복잡한 연구 설계에는 opusplan + xhigh + plan mode를 기억하세요.
