Hooks & 자동화

고급 05  Claude가 도구를 실행할 때 자동으로 쉘 명령을 실행 — 백업, 로그, 안전장치 자동화

Hooks는 Claude가 특정 행동(파일 쓰기, 명령 실행 등)을 하기 직전·직후에 사용자가 정의한 쉘 명령을 자동으로 실행하는 기능입니다. 예를 들어 Claude가 파일을 수정할 때마다 자동으로 백업을 만들거나, 완료 후 Git 커밋을 자동화할 수 있습니다.

💡 이 기능은 Claude Code CLI 전용

Hooks는 터미널에서 Claude Code를 실행할 때만 동작합니다. 웹 인터페이스(claude.ai)에서는 사용할 수 없습니다.

1. Hook의 종류

PreToolUse
도구 실행 전
Claude가 도구(파일 쓰기, 명령 실행 등)를 실행하기 직전에 실행됩니다. 조건 검사, 백업 생성에 적합합니다.
PostToolUse
도구 실행 후
Claude가 도구를 실행한 직후에 실행됩니다. 자동 Git 커밋, 알림 발송, 로그 기록에 적합합니다.

그 외에도 세션 시작/종료, 알림 발송 등에 쓰이는 Hook 이벤트가 있습니다:

이벤트발동 시점주요 용도
PreToolUseClaude가 어떤 도구를 사용하기 직전백업, 사전 검사
PostToolUseClaude가 어떤 도구를 사용한 직후Git 커밋, 로그 기록
NotificationClaude가 알림을 발행할 때 (긴 작업 대기 등)macOS/Windows 알림
StopClaude가 응답을 마칠 때완료 신호, 사운드
SubagentStop하위 에이전트가 작업을 마칠 때병렬 에이전트 완료 추적

2. 설정 파일 — settings.json

Hook은 ~/.claude/settings.json(전역) 또는 프로젝트의 .claude/settings.json에서 설정합니다. 설정 파일이 없으면 먼저 생성합니다.

# 전역 설정 파일 — 없으면 생성 (Mac/Linux)
echo '{}' > ~/.claude/settings.json
open ~/.claude/settings.json   # 텍스트 편집기로 열기

기본 JSON 구조

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write",    // ← 어떤 도구에 적용할지
        "hooks": [
          {
            "type": "command",
            "command": "git add . && git commit -m 'auto: Claude 파일 수정'"
          }
        ]
      }
    ]
  }
}

matcher — 적용 도구 지정

matcher에는 Claude 도구 이름을 문자열로 지정합니다. 비워두거나 matcher 키 자체를 생략하면 해당 이벤트의 모든 도구 실행에 적용됩니다.

matcher 값적용 도구대표 활용
Write파일 쓰기(생성/덮어쓰기)파일 수정 후 Git 커밋
Edit파일 부분 수정수정 전 자동 백업
Bash쉘 명령 실행실행 명령 로그 기록
Read파일 읽기접근 기록 감사
(생략 또는 "")해당 이벤트의 모든 도구세션 전체 활동 로그
💡 matcher 정규식도 가능

도구 이름에 부분 문자열을 지정할 수 있습니다. 예: "Write|Edit"는 파일 관련 도구 모두에 적용됩니다.

3. Hook 실행 동작 이해하기

실행 흐름

도구 실행 요청
→
PreToolUse Hook 실행
→
실제 도구 실행
→
PostToolUse Hook 실행
→
Claude 작업 계속

Hook은 도구 전후에 끼어드는 "사이드 이펙트"입니다. Claude의 주 작업 흐름은 계속 진행됩니다.

Hook 실패 시 동작

💡 Hook 실패는 Claude 작업을 중단하지 않습니다

Hook 명령이 오류 코드를 반환하거나 실패해도 Claude의 주 작업은 그대로 계속 진행됩니다. Hook은 "부가 작업"이므로 실패해도 Claude가 하던 일을 멈추지 않습니다.

예: Git이 설치되지 않아 git commit Hook이 실패해도 Claude의 파일 수정은 정상 완료됩니다.

여러 Hook 등록 시 실행 순서

같은 이벤트에 여러 Hook을 등록하면 배열에 정의된 순서대로 순차 실행됩니다. 앞 Hook이 실패해도 다음 Hook은 계속 실행됩니다.

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write",
        "hooks": [
          {
            "type": "command",
            "command": "echo \"[$(date)] 수정\" >> ~/claude_activity.log"   // ← 1번째 실행
          },
          {
            "type": "command",
            "command": "cd \"$CLAUDE_PROJECT_DIR\" && git add . && git commit -m 'auto'"   // ← 2번째 실행
          }
        ]
      }
    ]
  }
}
1
로그 기록 먼저 — 빠른 작업을 앞에 배치해 순서 의존성 예방
2
Git 커밋 나중에 — 느리거나 실패 가능성 있는 작업은 뒤에 배치
★
권장 순서: 로그 → 백업 → Git → 알림 순으로 배치하면 중요도 높은 작업부터 실행됩니다

4. 연구자 실용 Hook 예제

💾
파일 수정 전 자동 백업
Claude가 논문 파일을 수정하기 전에 .backup 확장자로 복사본을 만듭니다.
📌
수정 후 자동 Git 커밋
파일 수정이 완료될 때마다 자동으로 Git 커밋을 생성해 이력을 남깁니다.
📋
작업 로그 기록
Claude가 실행한 모든 명령과 시각을 로그 파일에 자동으로 기록합니다.
🔔
완료 알림
긴 분석 작업이 끝나면 운영체제 알림 또는 소리로 완료 신호를 보냅니다.

예제 1 — 파일 수정 후 자동 Git 커밋

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write",
        "hooks": [
          {
            "type": "command",
            "command": "cd \"$CLAUDE_PROJECT_DIR\" && git add . && git commit -m \"auto: $(date '+%H:%M') Claude 수정\" --quiet"
          }
        ]
      }
    ]
  }
}

예제 2 — 작업 완료 시 알림 (macOS / Windows)

{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "osascript -e 'display notification \"Claude 작업이 완료되었습니다\" with title \"Claude Code\" sound name \"Glass\"'"
          }
        ]
      }
    ]
  }
}

소리 없이 알림만 원하면 sound name "Glass" 부분을 제거하세요. 소리만 원하면 afplay /System/Library/Sounds/Glass.aiff를 사용합니다.

{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "powershell -Command \"Add-Type -AssemblyName System.Windows.Forms; [System.Windows.Forms.MessageBox]::Show('Claude 작업이 완료되었습니다', 'Claude Code')\""
          }
        ]
      }
    ]
  }
}

팝업 없이 토스트 알림을 원하면 PowerShell BurntToast 모듈(Install-Module BurntToast)을 설치 후 New-BurntToastNotification -Text "Claude 완료"를 사용합니다.

예제 3 — 쉘 명령 실행 전 로그 기록

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "echo \"[$(date '+%Y-%m-%d %H:%M:%S')] Bash 실행 (도구: $CLAUDE_TOOL_NAME)\" >> ~/.claude/session.log"
          }
        ]
      }
    ]
  }
}

5. Hook 설정 절차

  1. settings.json 파일 열기

    # 전역 설정 파일 — 없으면 먼저 생성
echo '{}' > ~/.claude/settings.json
open ~/.claude/settings.json

# 또는 nano/vim으로 편집
nano ~/.claude/settings.json

  2. hooks 블록 추가

    기존 JSON 구조에 "hooks" 키를 추가합니다. 다른 설정(mcpServers 등)이 있다면 쉼표로 구분해 추가합니다.

    {
  "mcpServers": { ... },   // 기존 MCP 설정
  "hooks": {              // 새로 추가
    "PostToolUse": [ ... ]
  }
}

  3. 저장 후 Claude 재시작

    설정 파일 저장 후 현재 Claude Code 세션을 종료하고 다시 시작합니다.

    # 현재 세션 종료 후 새 세션 시작
exit
claude

  4. 테스트

    Claude에게 간단한 파일 수정을 요청해서 Hook이 정상 실행되는지 확인합니다. 로그 Hook을 설정했다면 로그 파일로 확인합니다.

    # 로그 확인
cat ~/.claude/session.log

# Git 커밋 Hook이라면
git log --oneline -5

6. Hook 디버깅

Hook이 예상대로 작동하지 않을 때 다음 방법으로 원인을 파악합니다.

  • 📂
    로그 파일 확인
    ~/.claude/logs/ 폴더에 Hook 실행 로그가 저장됩니다. 
    # 최근 로그 확인
ls -lt ~/.claude/logs/
cat ~/.claude/logs/hooks.log   # 파일명은 버전마다 다를 수 있음
  • 🐛
    --mcp-debug 플래그 사용
    Claude Code를 디버그 모드로 실행하면 Hook 실행 결과가 터미널에 출력됩니다. 
    claude --mcp-debug
  • 🔍
    명령을 직접 터미널에서 테스트
    Hook에 등록한 명령을 터미널에서 직접 실행해 오류를 확인합니다. 
    # 예: Git 커밋 Hook 명령 직접 테스트
cd "$HOME/your-project" && git add . && git commit -m "test"
  • ✅
    JSON 문법 오류 확인
    settings.json에 문법 오류가 있으면 Hook 전체가 무시됩니다. 
    # Python으로 JSON 유효성 검사
python3 -m json.tool ~/.claude/settings.json

흔한 오류와 해결 방법

증상원인해결
Hook이 아예 실행 안 됨 settings.json JSON 문법 오류 또는 파일 위치 오류 python3 -m json.tool settings.json으로 유효성 검사
Git 커밋 Hook 실패 프로젝트 폴더가 Git 저장소가 아님, 또는 커밋할 변경사항 없음 git init으로 저장소 생성, 또는 git add . && git diff --cached --quiet || git commit으로 변경사항 있을 때만 커밋
osascript 알림 안 뜸 macOS 알림 권한 미승인 시스템 설정 → 알림 → 터미널 앱 알림 허용
환경 변수 비어있음 $CLAUDE_PROJECT_DIR는 프로젝트 지정 시에만 설정됨 Claude Code를 claude --project /path로 시작하거나 $PWD로 대체

7. 주의사항 및 환경 변수

⚠️ Hook은 자동 실행됩니다

Hook에 등록된 명령은 사용자 확인 없이 자동으로 실행됩니다. rm -rf 같은 파괴적인 명령은 절대 Hook에 포함하지 마세요. 처음에는 echo나 로그 기록처럼 안전한 명령으로 시작하세요.

💡 Hook 비활성화

특정 세션에서 Hook 없이 실행하려면 --no-hooks 플래그와 함께 시작합니다.

claude --no-hooks
💡 Hook 명령에서 사용할 수 있는 환경 변수
  • $CLAUDE_PROJECT_DIR — 현재 작업 중인 프로젝트 폴더 경로 (프로젝트 지정 시)
  • $CLAUDE_TOOL_NAME — 실행된 도구 이름 (Write, Bash, Edit 등)
  • $PWD — 현재 디렉토리 (CLAUDE_PROJECT_DIR 대안으로 사용 가능)

8. 연구 자동화 패턴 정리

목표Hook 이벤트명령 예시OS
파일 수정 이력 자동 저장 PostToolUse(Write) git add . && git commit -m "auto" All
긴 분석 완료 알림 Stop osascript -e 'display notification ...' Mac
긴 분석 완료 알림 Stop powershell -Command "... MessageBox ..." Windows
분석 완료 소리 Stop afplay /System/Library/Sounds/Glass.aiff Mac
명령 실행 로그 PreToolUse(Bash) echo "[$(date)] ..." >> session.log All
결과 파일 백업 PreToolUse(Edit/Write) cp "$FILE" "$FILE.bak" Mac/Linux
✅ 고급 파트를 모두 마쳤다면

Git으로 연구 이력을 관리하고, Worktree로 실험적 작업을 분리하고, Skill로 반복 작업을 자동화하고, MCP로 외부 도구를 연결하며, Hook으로 작업 후 처리를 자동화하는 전체 워크플로우를 구성할 수 있습니다. 이 흐름이 하나로 연결될 때 Claude는 단순한 채팅 도구를 넘어 진정한 연구 보조 시스템이 됩니다.
