단축키 및 기본 조작

활용 02  Claude Code 터미널 조작에 필요한 핵심 단축키와 슬래시 명령어

Claude Code는 터미널에서 실행되므로 마우스 대신 키보드로 대부분을 조작합니다. 자주 쓰는 단축키 10여 개와 슬래시 명령어를 익혀두면 작업 속도가 크게 달라집니다.

💡 읽는 방법

이 페이지의 단축키는 운영체제별로 표기합니다. Cmd는 Mac의 ⌘ 키이고, Ctrl은 Windows/Linux의 Control 키입니다. 각주*는 페이지 하단 주석을 참고하세요.

1. 프롬프트 입력 중 단축키

Claude에게 메시지를 작성하는 도중에 사용하는 단축키입니다.

Enter
메시지 전송

작성한 프롬프트를 Claude에게 보냅니다. 기본 전송 키입니다.

Shift + Enter
줄바꿈 (전송 없이)

프롬프트 안에서 줄바꿈을 합니다. 긴 프롬프트를 여러 줄로 정리할 때 사용합니다. ①

↑ / ↓
이전/다음 프롬프트 이동

이전에 입력한 프롬프트 내역을 불러옵니다. 비슷한 작업을 반복할 때 편리합니다.

Esc
입력 취소 / 모드 나가기

작성 중이던 내용을 지웁니다. Claude가 작업 중일 때 누르면 현재 작업을 중단할 수 있습니다.

2. Claude가 응답·작업 중일 때 단축키

Claude가 파일을 수정하거나 긴 답변을 생성하는 도중에 사용합니다.

Ctrl + C
작업 즉시 중단

Claude가 현재 수행 중인 작업을 즉시 멈춥니다. 잘못된 방향으로 가고 있을 때 사용하세요. ②

Shift + Tab
모드 순환 전환 ③

누를 때마다 아래 세 가지 모드를 순서대로 전환합니다. 현재 모드는 프롬프트 입력창 왼쪽에 표시됩니다.

표시 모드 이름 동작
(빈칸) 일반 모드 (기본) 파일 수정마다 직접 수락/거절
accept edits on 자동 수락 모드 수정 제안을 확인 없이 자동 적용 ⚠️
plan mode on 계획 모드 파일을 실제로 건드리지 않고 계획만 설명
Tab
제안 수락

Claude가 파일 수정 내용을 보여줄 때 "수락"을 선택합니다. 하나씩 확인하며 진행할 때 사용합니다. Enter도 동일하게 수락으로 작동합니다.

💡 Shift+Tab 계획 모드 × /model opusplan 연계

Shift+Tab으로 plan mode on을 켠 상태에서 /model opusplan을 설정하면, 계획 단계는 Opus(더 깊은 추론)가, 실행 단계는 Sonnet(빠르고 효율적)이 자동으로 담당합니다. 복잡한 분석 설계나 다단계 논문 작업에서 품질과 비용을 동시에 잡는 조합입니다. 자세한 내용은 활용 05 — 모델 선택과 사고 깊이를 참고하세요.

3. 슬래시 명령어 (/) — 도구 모음

프롬프트 창에 /로 시작하는 명령어를 입력하면 Claude Code의 내장 기능을 실행할 수 있습니다. 대화 내용을 다루거나 설정을 변경할 때 사용합니다.

자주 쓰는 슬래시 명령어

/help
명령어 목록 보기

사용 가능한 모든 슬래시 명령어 목록을 표시합니다. 처음 사용할 때 먼저 실행해보세요.

/clear
대화 내역 초기화

현재 세션의 대화 내역을 전부 지웁니다. 새로운 주제로 전환할 때 사용하면 Claude의 컨텍스트가 새로 시작됩니다. ④

/clear
/compact
컨텍스트 압축

대화가 길어져 컨텍스트 창이 가득 찰 때, 이전 내용을 요약해서 공간을 확보합니다. 작업의 흐름은 유지됩니다. ⑤

/compact
/cost
누적 비용 확인

이번 세션에서 사용한 토큰 수와 예상 비용($)을 표시합니다. "얼마나 썼나?"를 확인하는 명령어입니다.

/cost
/context
컨텍스트 창 사용률 확인

현재 컨텍스트 창이 얼마나 채워졌는지 퍼센트로 표시합니다. Claude Code는 창이 가득 차면 자동으로 정리하므로 평소에는 신경 쓰지 않아도 됩니다.

/context
/status
현재 상태 확인

Claude Code 버전, 현재 작업 폴더, 모델 정보 등을 표시합니다.

/status
/memory
메모리(CLAUDE.md) 편집

CLAUDE.md 파일을 빠르게 열어 편집할 수 있습니다. 프로젝트 맥락을 업데이트할 때 사용합니다.

/memory
/model
AI 모델 변경

사용할 Claude 모델을 별칭(alias)으로 간편하게 지정합니다. 인수 없이 /model만 입력하면 피커가 열립니다. 피커에서 좌우 방향키로 effort 슬라이더도 함께 조정할 수 있습니다.

별칭 동작 추천 상황
sonnet최신 Sonnet — 빠르고 균형 잡힘일상적 연구 작업
opus최신 Opus — 가장 강력한 추론복잡한 분석·설계
haiku빠르고 저렴한 경량 모델단순 요약·번역
opusplan계획=Opus, 실행=Sonnet 자동 전환복잡한 다단계 작업
opus[1m]Opus + 100만 토큰 컨텍스트매우 긴 문서 분석
/model opusplan   # 계획=Opus, 실행=Sonnet /model sonnet     # Sonnet으로 돌아오기

→ 더 자세한 설명: 활용 05 — 모델 선택과 사고 깊이

/effort
사고 깊이(Effort) 조절

Claude가 얼마나 깊이 생각할지를 설정합니다. 높을수록 품질이 높아지지만 토큰(비용)이 더 소모됩니다. low·medium·high·xhigh는 세션 간 유지되며, max는 현재 세션에만 적용됩니다.

레벨 의미 추천 상황
low빠른 응답, 최소 추론단순 번역·형식 변환
medium균형 잡힌 추론비용 절감이 중요할 때
high기본값(Opus 4.6/Sonnet)일반 연구 작업
xhigh기본값(Opus 4.7) — 대부분 최적복잡한 분석·논문 작성
max제한 없는 최대 추론 (세션한정)가장 까다로운 작업
/effort xhigh   # 직접 설정 /effort         # 슬라이더로 선택 /effort auto    # 모델 기본값으로 리셋
💡 ultrathink — 일회성 최대 추론

프롬프트에 ultrathink를 포함하면 effort 설정을 바꾸지 않고 그 답변에서만 최대로 깊이 생각합니다. 예: "이 연구 방법론의 한계를 ultrathink로 검토해줘"

→ 시나리오별 추천 설정: 활용 05 — 모델 선택과 사고 깊이

/exit
Claude Code 종료

Claude Code를 종료하고 터미널로 돌아옵니다. Ctrl+D로도 종료할 수 있습니다.

/exit

/cost vs /context — 헷갈리는 두 명령어 차이

/cost /context
묻는 질문 이번 세션에 돈(토큰)을 얼마나 썼나? 컨텍스트 창이 얼마나 찼나?
표시 내용 입력·출력 토큰 수, 예상 비용($) 컨텍스트 창 사용률 (%)
비유 택시 요금계 (누적 금액) 연료 게이지 (현재 잔량)
언제 확인 긴 작업 후 비용 파악할 때 대화가 길어져 느려질 것 같을 때
한계 도달 시 Pro 플랜 사용량 초과 위험 /compact 또는 /clear 권장
💡 상태창(Status Bar)에서 실시간 확인

Claude Code 화면 하단의 상태창(status bar)에는 현재 세션의 컨텍스트 사용률 %가 실시간으로 표시됩니다. 별도 명령어 없이도 항상 볼 수 있습니다.

상태창에 표시되는 숫자가 70% 이상이 되면 슬슬 /compact를 실행하는 것이 좋습니다. 90% 이상이 되면 Claude 응답이 느려지거나 맥락을 잃기 시작합니다.

상태창이 보이지 않는다면: Claude Code 실행 후 화면 맨 아래 줄을 확인하세요. /status 명령어로도 현재 컨텍스트 상태를 확인할 수 있습니다.

4. 파일·폴더 참조하기

Claude에게 특정 파일이나 폴더를 작업하도록 지시할 때는 아래 방법을 사용합니다.

방법 A — @ 기호로 파일 지정

프롬프트 안에서 @를 입력하면 파일 자동완성이 나타납니다.

✍️ 프롬프트 예시

@04_writing/draft_intro.md 를 읽고 서론의 연구 목적 단락이 APA 7판 형식에 맞는지 확인해줘.

방법 B — 파일 경로 직접 입력

✍️ 프롬프트 예시

03_analysis/cfa_results.csv 파일의 요인부하량 값들을 보고 APA 형식 표로 만들어줘. 표를 04_writing/table2_cfa.md로 저장해줘.

방법 C — 여러 파일 동시에

✍️ 프롬프트 예시

01_literature 폴더의 PDF들을 모두 확인하고, 각 논문의 제목·저자·연도·핵심 주장을 정리해서 references.md 파일로 만들어줘.

5. 일반적인 작업 흐름

Claude와 함께 작업할 때의 전형적인 흐름입니다. 파일 수정 제안이 나타나면 반드시 내용을 확인한 후 수락하세요.

① 프롬프트 작성
→
작업 내용을 구체적으로 입력합니다
② Enter 전송
→
Claude가 파일을 읽고 분석을 시작합니다
③ 작업 확인
→
Claude가 수정 내용을 보여줍니다 (diff 형식)
④ Tab으로 수락
→
내용이 마음에 들면 Tab 키로 수락합니다
⑤ 추가 지시
→
수정이 필요하면 보완 지시를 입력합니다
⚠️ 수락 전에 반드시 확인

Claude가 제안한 파일 수정 내용은 반드시 읽어보고 수락하세요. 특히 데이터 파일이나 분석 코드는 의도치 않은 변경이 생길 수 있습니다. CLAUDE.md에 "수정 금지" 파일을 명시해두는 것이 안전합니다.

주석

①
터미널에 따라 Shift+Enter 대신 Option+Enter(Mac) 또는 Alt+Enter(Windows)가 줄바꿈으로 동작하는 경우가 있습니다. 설정되지 않은 경우 그냥 Enter를 치면 전송되므로, 긴 프롬프트는 텍스트 에디터(메모장, 메모)에서 먼저 작성한 후 붙여넣는 방법도 있습니다.
②
Ctrl+C는 터미널의 표준 인터럽트 신호입니다. Claude가 작업 중일 때 누르면 현재 수행 중인 도구 호출을 중단하고 프롬프트 입력 상태로 돌아옵니다. 파일에 부분적으로 저장이 이루어진 경우 확인이 필요합니다.
③
Shift+Tab을 누를 때마다 모드가 순서대로 바뀝니다: 일반 → 자동 수락 → 계획 → 일반 … 현재 모드는 프롬프트 입력창 왼쪽에 표시됩니다. 아무것도 표시되지 않으면 일반 모드(기본)입니다. 자동 수락(accept edits on) 모드는 파일 수정을 확인 없이 바로 적용하므로, 중요한 파일을 다룰 때는 주의하세요. 계획(plan mode on) 모드는 Claude가 실제로 파일을 수정하지 않고 무엇을 할지 설명만 하는 상태입니다. "이렇게 수정해도 될까?"를 먼저 확인하고 싶을 때 유용합니다.
④
/clear는 현재 세션의 대화 내역만 지웁니다. CLAUDE.md 파일은 그대로 남아 있어 다음 메시지부터 다시 읽힙니다. 따라서 프로젝트 맥락은 유지되면서 대화를 새로 시작할 수 있습니다.
⑤
Claude Code의 컨텍스트 창은 Pro 플랜 기준 약 200,000 토큰입니다. 한 세션에서 긴 논문 초안을 여러 번 주고받다 보면 가득 찰 수 있습니다. /compact를 실행하면 이전 대화를 요약해서 공간을 확보하므로 작업 흐름을 유지하면서 계속할 수 있습니다.
✅ 이 장을 마쳤다면

Enter/Ctrl+C/Shift+Tab의 역할을 알고 있으며, /clear와 /compact의 차이를 이해하고 있어야 합니다. 또한 /model opusplan으로 계획과 실행 모델을 분리하는 전략, /effort로 사고 깊이를 조절하는 방법을 익혔습니다. 모델 선택과 effort 설정을 더 깊이 이해하려면 활용 05 — 모델 선택과 사고 깊이를 읽어보세요.
