커스텀 Skill 제작

고급 03  v2  Skill 호출 문법, 전역/프로젝트 판단 기준, 작동 테스트 절차 강화

Skill은 자주 쓰는 프롬프트 패턴을 마크다운 파일로 저장해 두고 /skill-name 명령으로 즉시 불러오는 기능입니다. 같은 지시를 매 세션마다 타이핑하는 대신, 한 번 작성해 두면 영구적으로 재사용할 수 있습니다.

💡 이 기능은 어디에 있나요?

Skill은 Claude Code (CLI 및 데스크탑 앱) 환경에서 동작합니다. claude.ai 웹 인터페이스에는 없는 기능입니다. Claude Code 설치가 완료되어 있어야 합니다 (설치 가이드).

1. 언제 Skill을 만드나

🔁
반복 패턴
매 세션마다 같은 지시를 타이핑하고 있다면 Skill로 만들 타이밍입니다.
📐
형식 일관성
APA 인용, 요약 형식 등 정확한 형식이 중요한 작업에 적합합니다.
📢
팀 공유
연구팀 전원이 동일한 프롬프트 패턴을 쓸 수 있도록 표준화합니다.
🎯
복잡한 지시
여러 단계의 지시문이나 조건부 처리가 필요한 복잡한 작업을 저장합니다.

2. Skill 만들기 — Claude에게 요청하면 됩니다

파일 구조나 경로를 직접 다룰 필요 없습니다. 원하는 스킬을 말로 설명하면 Claude가 파일을 만들고 저장합니다.

  • 1
    원하는 스킬을 말로 설명

    어떤 작업인지, 어떤 형식으로 결과를 원하는지 설명합니다. 파일명도 함께 알려주면 바로 저장됩니다.

    Terminal — Claude Code (CLI)
    > 논문 리뷰어 코멘트에 반박문을 작성하는 스킬 만들어줘. 학술지 제출용이고, APA 스타일, 정중하지만 단호한 톤으로. 파일명은 rebuttal 로 해줘.
  • 2
    Claude가 파일 생성 및 저장

    Claude가 스킬 파일을 작성하고 자동으로 저장합니다. 완료 메시지를 확인하면 됩니다.

    Terminal — Claude 응답
    ✓ Write ~/.claude/skills/rebuttal.md 스킬이 생성됐습니다. 다음 세션부터 /rebuttal 로 호출하세요.
    스킬명 변경하고 싶다면? 파일명이 곧 호출 명령어입니다. 만든 후 이름을 바꾸려면 Claude에게 "스킬 파일명을 review-reply로 바꿔줘"라고 하거나, 파일명을 직접 수정하면 됩니다.
  • 3
    새 세션에서 호출

    Skill은 다음 세션(새로 실행한 claude)부터 인식됩니다. /스킬명으로 호출하고 작업 대상을 덧붙입니다.

    Terminal — 다음 세션
    # 세션 재시작 후 > /rebuttal 리뷰어 2번 코멘트 반박문 작성해줘. reviewer_comments.md 파일 참고해서. Read reviewer_comments.md 리뷰어 2번 코멘트: "측정 도구의 타당도 검증이 부족함" 반박문 초안: Dear Reviewer 2, We appreciate your detailed feedback regarding the validity of measurement instruments...

요청할 때 이 정보를 추가하면 더 좋습니다

없어도 만들어지지만, 아래 정보를 포함하면 첫 번째 결과물 품질이 높아집니다.

🎯
어떤 상황에서 쓸 건지
매번 쓰는 건지, 특정 논문에서만 쓰는 건지
"투고할 때마다 써" / "이 연구에서만 써"
📋
원하는 출력 형식
표 / 특정 양식 / 글자 수 제한 / 언어
"표로 / APA / 250자 이내 / 한국어 먼저"
✍️
기존에 선호하는 방식
항상 지키는 규칙이나 스타일이 있다면
"bullet point, 결론 먼저, 수동태 지양"

3. Skill 호출 방법

Skill을 만든 후에는 Claude Code 세션에서 /skill-name으로 호출합니다. 호출 방식에 따라 다양하게 활용할 수 있습니다.

호출 패턴별 예시

같은 Skill을 다양한 방식으로 호출할 수 있습니다.

/apa-citation
→ Skill만 호출. Skill 본문대로 동작 (추가 지시 없음)
/apa-citation
01_literature 폴더의 논문들을 정리해줘. 04_writing/references.md에 저장.
→ 가장 일반적인 방식. Skill을 호출하면서 구체적 대상(폴더, 파일)과 저장 경로를 추가로 지정
/abstract-writer
04_writing/chapter_draft.md 읽고 영문 초록도 함께 만들어줘 (200 words).
→ Skill에 없는 추가 요청(영문 초록)을 그 자리에서 덧붙이기 가능. Skill + 임시 지시의 조합
💡 Skill은 CLAUDE.md 맥락을 함께 사용합니다

Skill 호출 시 Claude는 현재 프로젝트의 CLAUDE.md도 함께 참조합니다. CLAUDE.md에 "APA 7판 사용, 한국어 먼저 정렬"이라고 정의되어 있으면 /apa-citation 호출 시 그 맥락이 자동 반영됩니다.

4. 연구자 맞춤 Skill 예제

예제 1 — APA 7판 인용 정리

~/.claude/skills/apa-citation.md
--- name: apa-citation description: 논문 정보나 폴더의 파일을 APA 7판 형식 참고문헌으로 정리 --- 사용자가 제공한 논문 정보 또는 지정한 폴더의 파일들을 바탕으로 APA 7판 형식 참고문헌 목록을 작성하세요. ## 규칙 - 알파벳/가나다 순 정렬 (한국어 먼저, 이후 영문) - 저자 3명 이상: 첫 저자 et al. (한국어: 첫 저자 외) - DOI는 https://doi.org/ 형식으로 표기 - 학술지명, 도서명은 이탤릭체 (*이탤릭*) - 권(호) 형식: *학술지명, 권*(호), 쪽수 ## 출력 마크다운 형식으로 참고문헌 목록만 출력하세요. 파일 저장 경로를 지정받으면 해당 파일에 저장합니다.
✍️ 호출 예시

/apa-citation
01_literature 폴더에 있는 논문들을 정리해줘. 04_writing/references.md에 저장.

예제 2 — 논문 초록 작성

~/.claude/skills/abstract-writer.md
--- name: abstract-writer description: 논문 본문을 바탕으로 한국교육학회 스타일 국문 초록 작성 (250자 이내) --- 사용자가 제공한 논문 본문(또는 지정 파일)을 읽고 한국교육학회 투고 규정에 맞는 국문 초록을 작성하세요. ## 구성 (이 순서대로) 1. 연구 목적 (1-2문장) 2. 연구방법 요약 (참여자/대상, 분석 방법) 3. 주요 결과 (2-3가지 핵심 발견) 4. 결론 및 함의 (1문장) ## 형식 - 총 250자 이내 - 주어-서술어 명확한 완결 문장 - 수동태 지양, 능동태 사용 - 전문 용어는 원문 그대로 유지 ## 출력 초록 본문만 출력. 제목, 설명 불필요.

예제 3 — 질적 코딩 보조

~/.claude/skills/qualitative-code.md
--- name: qualitative-code description: 인터뷰 전사본에서 귀납적 초기 코드 목록 추출 (Braun & Clarke 2006 주제분석) --- 사용자가 제공한 인터뷰 전사본을 읽고 Braun & Clarke(2006) 주제 분석법 2단계(초기 코딩)를 수행하세요. ## 작업 절차 1. 전사본 전체를 읽고 반복되거나 강조된 의미 단위 파악 2. 각 의미 단위에 간결한 코드명 부여 (명사형, 5단어 이내) 3. 코드명 + 해당 원문 인용 + 코드 메모 한 줄 작성 4. 유사 코드끼리 잠정적 범주 제안 (5-7개) ## 출력 형식 (마크다운 표) | 코드명 | 원문 인용 | 코드 메모 | |---|---|---| | ... | "..." | ... | 이후 잠정적 범주와 포함 코드 목록. ## 주의 - 한 번에 한 참여자 파일만 처리 (순차 반복 원칙) - 코드는 현상을 기술하되 해석을 최소화 - 상충하는 증거도 코드로 포함

예제 4 — 주차별 리딩 리플렉션 페이퍼 (실제 활용 사례)  ⚡ 고급 활용 예시

💡 이런 상황에서 만들었습니다

매주 수업 전날 Google Drive의 주차별 폴더에 담긴 논문 PDF(3-5편)를 읽고 리플렉션 페이퍼를 작성해야 할 때 — 폴더 탐색, 논문 요약, docx 파일 생성까지 한 번의 명령으로 끝냅니다.

~/.claude/skills/week/SKILL.md
--- name: week description: 주차별 리딩 폴더의 PDF를 읽고 리플렉션 페이퍼(.docx)를 작성합니다. 사용법: /week [숫자] --- 사용자 입력에서 주차 번호를 추출하세요. (/week 2 → 2주차) ## 1. 파일 탐색 Google Drive에서 Week {숫자} 폴더를 찾아 PDF 목록을 확인합니다. 경로: ~/Library/CloudStorage/GoogleDrive-.../비교교육(청강)/교수님 자료/Week {숫자} ## 2. 논문 요약 (서브에이전트 병렬 처리) 각 PDF를 독립적인 서브에이전트로 동시에 처리합니다. 요약 항목: 저자/연도 · 핵심 주장 · 이론적 틀 · 비판 가능한 지점 · 다른 문헌과의 연결 ## 3. 리플렉션 페이퍼 작성 (python-docx) 출력 파일: Week{숫자}_Reflection.docx 저장 경로: .../비교교육(청강)/리플렉션 페이퍼/ 문서 구성: 들어가며 → 내용 정리 → 비판적 성찰 → 나가며 분량: A4 3-5장 · 한국어 · 학문적 어조 · 저자명/연도 인용
✍️ 호출 예시

/week 2  또는  /week 11 — 주차 번호만 바꾸면 됩니다.

Terminal — 실행 흐름
> /week 2 Week 2 폴더를 탐색하고 있습니다... → PDF 3편 발견: Archer(2000), Reay(2004), Bourdieu(1990) 서브에이전트로 병렬 요약 중... ✓ Archer_2000.pdf 요약 완료 ✓ Reay_2004.pdf 요약 완료 ✓ Bourdieu_1990.pdf 요약 완료 ✓ Write .../리플렉션 페이퍼/Week2_Reflection.docx 완료 — 논문 3편 처리 이번 주 주제: 교육에서의 행위주체성(agency)과 구조의 관계
⚠️ Skill 인식 안 될 때

/스킬명을 입력했을 때 반응이 없다면 현재 세션에서 만든 경우입니다. Skill은 새 세션부터 인식됩니다. Claude를 종료 후 다시 실행해 보세요.

5. CLAUDE.md vs Skill — 언제 어떤 것을 쓰나

CLAUDE.mdSkill
용도프로젝트 전반에 항상 적용되는 맥락특정 작업에 명시적으로 호출하는 지시
활성화Claude Code 시작 시 자동 로드/skill-name으로 수동 호출
적합한 내용연구 주제, 대상, 사용 용어 정의, 문체APA 정리, 초록 작성, 코딩 보조 등 반복 작업
범위프로젝트 폴더에 위치 → 해당 프로젝트만전역/프로젝트 선택 가능
💡 함께 쓰는 방법

CLAUDE.md에는 프로젝트 맥락(연구 주제, 참여자 정보, 사용 통계 소프트웨어)을 넣고, Skill에는 반복 작업 절차를 넣습니다. Claude는 Skill 호출 시 CLAUDE.md의 맥락을 함께 참조해 더 정확한 결과를 냅니다.

✅ 이 장을 마쳤다면

원하는 작업을 말로 설명하면 Claude가 Skill을 만들어줍니다. 새 세션에서 /스킬명으로 호출하고, 호출 시 작업 대상이나 추가 지시를 덧붙일 수 있습니다. 스킬명 변경은 언제든 Claude에게 요청하거나 파일명을 직접 수정하면 됩니다.
