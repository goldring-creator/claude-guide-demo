Git 기초 (연구자용)

고급 01  논문 버전 관리, 실수 복구, Claude와 함께 쓰는 최소 Git 워크플로우

Git은 파일의 변경 이력을 저장하는 버전 관리 도구입니다. 개발자만 쓰는 도구처럼 보이지만 연구자에게도 실질적인 가치가 있습니다. "어제 쓴 문단으로 되돌아가고 싶다", "분석 코드를 바꿨는데 결과가 달라졌다"는 상황을 Git이 해결해 줍니다.

💡 이 장의 범위

Git 전체 기능이 아닌 연구자에게 실제로 필요한 최소 기능만 다룹니다. 브랜치 병합, 원격 저장소(GitHub) 협업 등 복잡한 내용은 다루지 않습니다.

1. 연구자에게 Git이 필요한 이유

많은 연구자가 파일 이름으로 버전을 관리합니다.

논문초안_최종.docx
논문초안_최종2.docx
논문초안_진짜최종.docx
논문초안_제출용_수정.docx

이 방식의 문제는 어떤 파일이 가장 최신인지 알 수 없고, 어떤 내용이 바뀌었는지 확인하기 어렵다는 점입니다. Git을 쓰면 하나의 파일에 여러 버전의 이력을 담고, 언제든 원하는 시점으로 돌아갈 수 있습니다.

🕰️
버전 복구
어제 쓴 서론, 지난주 분석 코드를 날짜 기준으로 불러올 수 있습니다.
🔍
변경 추적
어떤 문장이 언제 추가/삭제됐는지 비교할 수 있습니다.
🧪
실험적 수정
대담하게 수정하고, 마음에 안 들면 원래대로 되돌릴 수 있습니다.
🤖
Claude와 연동
Claude가 커밋 메시지 작성, 변경 이력 요약을 자동으로 처리합니다.

2. 핵심 개념 3가지

📦
저장소 (Repository)
Git이 이력을 관리하는 폴더 단위입니다. 연구 프로젝트 폴더 하나가 저장소 하나가 됩니다. .git 폴더가 생기면 저장소가 된 것입니다.
📸
커밋 (Commit)
특정 시점의 파일 상태를 저장하는 행위입니다. "1장 서론 완성"처럼 의미 있는 메시지를 붙여서 저장하면 나중에 찾기 쉽습니다.
📋
로그 (Log)
지금까지 저장된 커밋 목록입니다. 언제, 누가, 어떤 내용을 저장했는지 타임라인으로 확인할 수 있습니다.

3. Git 설치

Mac에는 Git이 기본 설치되어 있는 경우가 많습니다. 터미널에서 확인하세요.

git --version
# git version 2.x.x 가 나오면 설치 완료

설치가 안 되어 있다면 Xcode Command Line Tools 설치 또는 Homebrew로 설치합니다.

# Xcode Command Line Tools (권장)
xcode-select --install

# 또는 Homebrew로 설치
brew install git

Git for Windows를 설치합니다. 설치 시 Git Bash도 함께 설치되어 터미널처럼 사용할 수 있습니다.

  1. git-scm.com/download/win 접속
  2. 64-bit Git for Windows 다운로드 및 설치
  3. 설치 옵션은 기본값 유지 (모두 Next)

설치 후 PowerShell에서 확인:

git --version
# git version 2.x.x.windows.x 가 나오면 완료

4. 처음 한 번만 하는 기본 설정

Git은 커밋할 때 작성자 이름과 이메일을 기록합니다. 한 번만 설정하면 이후 모든 저장소에 적용됩니다.

git config --global user.name "홍길동"
git config --global user.email "hong@example.com"

# 설정 확인
git config --global --list
💡 한글 파일명 깨짐 방지

Mac/Linux에서 한글 파일명이 깨져 보일 수 있습니다. 아래 명령으로 예방하세요.

git config --global core.quotepath false

5. 연구자 기본 워크플로우

연구 프로젝트를 Git으로 관리하는 흐름은 다음과 같습니다.

  1. 저장소 초기화

    프로젝트 폴더로 이동 후 저장소를 만듭니다. 폴더 안에 .git 디렉터리가 생기고 이후 모든 변경사항이 추적됩니다.

    cd ~/Desktop/my-research
git init
# Initialized empty Git repository in ~/Desktop/my-research/.git/
    💡 노란색 경로는 본인 폴더 이름으로 바꾸세요.

  2. 파일 추가 (스테이징)

    저장할 파일을 선택합니다. .은 현재 폴더의 모든 파일을 의미합니다.

    # 특정 파일만 추가
git add 01_literature/review_notes.md

# 모든 변경 파일 추가
git add .

  3. 커밋 (저장)

    의미 있는 메시지를 붙여서 이력을 저장합니다. 짧고 명확하게 쓸수록 나중에 찾기 쉽습니다.

    git commit -m "1장 서론 초안 완성"
git commit -m "교사 소진 설문 데이터 전처리 완료"
git commit -m "2장 선행연구 검토 — 3편 추가"

  4. 이력 확인

    지금까지 저장된 커밋 목록을 확인합니다.

    git log --oneline
a3f9c12 2장 선행연구 검토 — 3편 추가
b7e2a01 교사 소진 설문 데이터 전처리 완료
c1d4f88 1장 서론 초안 완성

6. 연구자 필수 명령어

명령어용도예시
git status현재 변경된 파일 목록 확인커밋 전 어떤 파일이 바뀌었는지 확인
git add .모든 변경 파일을 스테이지에 올림커밋 전 파일 선택
git commit -m "메시지"현재 상태를 이력으로 저장작업 단위마다 저장
git log --oneline커밋 이력을 한 줄씩 표시어떤 작업을 했는지 돌아보기
git diff마지막 커밋 이후 변경 내용 확인어떤 문장이 수정됐는지 확인
git restore <파일>파일을 마지막 커밋 시점으로 되돌림실수한 수정 취소
git restore .모든 변경 파일 되돌림대규모 수정 취소

7. 실수 복구 방법

방법 1 — 마지막 커밋 이후 변경 취소

파일을 수정했지만 아직 커밋하지 않은 상태에서 되돌릴 때 사용합니다.

# 특정 파일 되돌리기
git restore 04_writing/chapter1.md

# 모든 파일 되돌리기
git restore .
⚠️ 주의

git restore는 커밋하지 않은 변경사항을 영구적으로 삭제합니다. 커밋된 내용만 복구 가능하므로, 중요한 작업 후에는 반드시 커밋을 먼저 하세요.

방법 2 — 특정 커밋 시점의 파일 꺼내기

수일 전 특정 커밋 시점의 파일 내용을 확인하거나 복원할 때 사용합니다.

# 커밋 해시 확인
git log --oneline
a3f9c12 2장 선행연구 검토 완료
b7e2a01 1장 서론 초안

# b7e2a01 커밋 시점의 파일 내용 확인
git show b7e2a01:04_writing/chapter1.md

8. .gitignore — 추적하지 않을 파일 지정

연구 데이터(개인정보), 임시 파일, 용량이 큰 바이너리 파일은 Git으로 추적하지 않는 것이 좋습니다. 프로젝트 폴더 최상위에 .gitignore 파일을 만들어 제외할 파일을 지정하세요.

# .gitignore 연구용 예시
# 원시 개인정보 데이터
03_data/raw/

# 임시 파일
*.tmp
*.bak
~$*

# macOS 시스템 파일
.DS_Store

# R/Python 캐시
.Rhistory
.RData
__pycache__/
*.pyc

# 용량 큰 파일 (SPSS 데이터 등)
*.sav
*.sas7bdat

9. Claude와 함께 Git 쓰기

Claude Code는 Git 명령어를 직접 실행할 수 있습니다. 커밋 메시지 작성이나 변경 내용 요약을 Claude에게 맡길 수 있습니다.

✍️ 프롬프트 예시

오늘 작업한 내용(git diff)을 보고 한국어로 커밋 메시지를 간결하게 만들어줘. 50자 이내로.

✍️ 프롬프트 예시

git log --oneline을 보고 지난 1주일간 어떤 작업을 했는지 3줄로 요약해줘.

💡 세션 시작 루틴에 추가하기

매 작업 시작 시 git status를 먼저 실행해서 어떤 파일이 수정된 상태인지 확인하는 습관을 들이세요. 작업 후에는 git add . && git commit -m "..."으로 마무리합니다.

✅ 이 장을 마쳤다면

git init → git add → git commit 흐름을 이해하고 있어야 합니다. 실수한 파일을 git restore로 되돌릴 수 있으며, git log로 이전 작업 이력을 확인할 수 있습니다.
